# 12 — نطاق الحد الأدنى القابل للإطلاق (MVP Scope)

الغرض من هذا الملف: **منع التضخّم (Over-Engineering)** برسم حدّ واضح لما يُبنى أولاً وما يُؤجَّل، حتى لا يبدأ الفريق ببناء نظام ضخم من اليوم الأول. المستند التصميمي شامل عمداً (مرجع كامل)، لكن **التنفيذ يتدرّج**.

> **مبدأ حاكم:** الوثيقة أشمل من الـ MVP بقصد. لا يُبنى بند إلا إذا كان في المرحلة الحالية. أي طلب خارج المرحلة يُسجَّل في Backlog ولا يُنفَّذ الآن.

---

## Phase 1 — MVP (القابل للإطلاق والاستخدام الفعلي)

**الهدف:** نظام يُشغّل المكتب يومياً في أهم وظيفتين: **الموظفون + الحضور**، فوق أساس آمن (مصادقة/صلاحيات).

### ✅ مشمول (In-Scope)
| المجال | التفصيل |
|--------|---------|
| **Authentication** | تسجيل دخول JWT + Refresh، تغيير كلمة المرور، إدارة الجلسات، MFA للأدوار الحساسة |
| **Users** | إدارة المستخدمين، ربطهم بالموظفين، تفعيل/تعطيل |
| **Roles & Permissions** | RBAC كامل + مصفوفة الصلاحيات + Policies الأساسية (ABAC للملكية/الفرع) |
| **Branches & Departments** | الهيكل التنظيمي الأساسي |
| **Employees (Basic HR)** | ملف الموظف الكامل، المستندات، البدلات/الخصومات، تنبيهات انتهاء العقد |
| **Attendance** | تسجيل يدوي + **تكامل جهاز بصمة واحد على الأقل (ZKTeco كأولوية)**، الاحتساب اليومي، التأخير/الغياب/الإضافي |
| **Leaves** | طلب/اعتماد/رفض + الأرصدة (دورة عمل كاملة) |
| **Dashboard أساسي** | مؤشرات HR + الحضور اللحظي + المهام المستحقة |
| **Tasks (أساسي)** | إنشاء/إسناد/حالة (يخدم كل الأقسام مبكراً) |
| **Notifications (In-App + Email)** | للأحداث الأساسية (إجازة/حضور/مهمة) |
| **Audit Logs** | تفعيل التدقيق من اليوم الأول (أساس أمني لا يؤجَّل) |
| **Documents (أساسي)** | رفع/تحميل مرفقات الموظفين |

### ❌ غير مشمول في Phase 1 (يُؤجَّل)
❌ المالية الكاملة (فواتير/قيود/محاسبة مزدوجة) · ❌ الرواتب الآلية · ❌ القضايا والجلسات · ❌ العملاء والعقود · ❌ التسويق/CRM · ❌ التقارير المتقدمة · ❌ SMS/Push · ❌ تعدد أجهزة/موردي البصمة · ❌ الذكاء الاصطناعي · ❌ بوابة العملاء.

**معيار قبول Phase 1 (Definition of Done):** موظف يبصم فتُحتسب ساعاته آلياً، ويقدّم إجازة فتُعتمد ويُخصم رصيده، ومدير النظام يدير المستخدمين والصلاحيات بأمان، مع تدقيق كامل.

---

## Phase 2 — التشغيل الأساسي للأعمال

**الهدف:** إضافة جوهر عمل مكتب المحاماة والمال.

### ✅ مشمول
| المجال | التفصيل |
|--------|---------|
| **Cases** | القضايا، الجلسات، المستندات القانونية، الأحكام، المذكرات |
| **Clients & Contracts** | العملاء (أفراد/شركات)، العقود، سجل التواصل |
| **Finance** | الفواتير، سندات القبض/الصرف، الصندوق/البنك، القيود المزدوجة، الضرائب |
| **Payroll (آلي)** | مسير رواتب متكامل مع الحضور + كشوف PDF |
| **Reports** | كل التقارير (HR/قضايا/مالية) مع PDF/Excel/طباعة |
| **Dashboard كامل** | كل المؤشرات المالية والقضائية |
| **Notifications كاملة** | SMS + تذكيرات الجلسات + الفواتير المستحقة |
| **E-Archive كامل** | الوسوم، الإصدارات، البحث النصي (Meilisearch) |
| **Performance Reviews** | تقييم الأداء |
| **Biometric متعدد** | دعم بقية الموردين (Hikvision/Suprema/Anviz) |

---

## Phase 3 — الإثراء والتوسّع

### ✅ مشمول
| المجال | التفصيل |
|--------|---------|
| **Marketing/CRM** | الحملات، Leads، Pipeline، التحويل |
| **Automation Engine** | قواعد أتمتة متقدمة، تقارير مجدولة، workflows |
| **Advanced Analytics** | لوحات تحليلية، ربحية القضية/العميل، تتبّع الوقت |
| **AI** | تلخيص المستندات، مساعد صياغة المذكرات، بحث دلالي |
| **Client Portal / Mobile** | بوابة عملاء + تطبيق جوّال |
| **Complex Integrations** | بوابات دفع، أنظمة محاكم، توقيع إلكتروني |
| **Multi-Tenant SaaS** | تفعيل `tenant_id` (حسب [ADR-005](adr/005-multitenancy-strategy.md)) |

## خريطة المراحل (ملخص بصري)

```
MVP Scope
│
├── Phase 1 (MVP) ──────────────► إطلاق مبكر واستخدام فعلي
│   ├── Authentication
│   ├── Users · Roles & Permissions
│   ├── Employees (Basic HR) · Leaves
│   ├── Attendance (+ جهاز بصمة واحد)
│   ├── Tasks · Notifications (In-App/Email)
│   └── Dashboard أساسي · Audit
│
├── Phase 2 ────────────────────► جوهر الأعمال
│   ├── Cases · Clients · Contracts
│   ├── Finance (كامل) · Payroll (آلي)
│   ├── Reports · E-Archive · Performance
│   └── Biometric (بقية الموردين)
│
└── Phase 3 ────────────────────► إثراء وتوسّع
    ├── Marketing/CRM
    ├── Automation · Advanced Analytics
    ├── AI · Client Portal · Mobile
    └── Multi-Tenant SaaS
```

## قواعد ضبط النطاق (Scope Guardrails)
1. **لا يُبنى بند من Phase 2/3 أثناء Phase 1** مهما بدا سهلاً — يُسجَّل في Backlog.
2. **كل ميزة خلف Feature Flag** لتفعيلها تدريجياً دون نشر جديد.
3. **إطلاق Phase 1 أولاً في الإنتاج** (Pilot) قبل بدء Phase 2 — تعلّم حقيقي قبل التوسّع.
4. **مراجعة النطاق** في نهاية كل مرحلة: ما الذي أثبت قيمته؟ ما الذي يُلغى/يُعاد ترتيبه؟
