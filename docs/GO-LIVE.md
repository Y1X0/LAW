# حزمة الإطلاق — Go-Live Package (LawFirm ERP)

المرجع الرئيسي لإطلاق النظام وتسليمه لشركة واحدة. الصفحة الأولى (الملخّص التنفيذي) تكفي مسؤول
الـ IT للتنفيذ؛ وما بعدها تفصيلٌ يُرجَع إليه عند الحاجة. **لا يكرّر** هذا الملف الأدلّة الأخرى بل
يربطها: [DEPLOY-RENDER](DEPLOY-RENDER.md) (تفاصيل النشر) · [BACKUP-RUNBOOK](BACKUP-RUNBOOK.md)
(النسخ/الاستعادة) · [RELEASE-STATUS](RELEASE-STATUS.md) (حالة الوحدات).

---

## ① الملخّص التنفيذي (صفحة واحدة)

**ما هو:** نظام ERP لمكتب محاماة (Laravel API + React SPA + Postgres) يُنشَر على Render عبر
Blueprint واحد (`render.yaml`): `law-api` (خلفية) · `law-web` (واجهة) · `law-postgres` (قاعدة) ·
`law-scheduler` (مهام مجدولة).

**قبل الإطلاق (Go/No-Go):** CI أخضر على `main` · كل الأسرار المطلوبة مضبوطة · الخطة مدفوعة
(`starter`+ للقاعدة والـ cron) · دلو R2 للنسخ منفصل · Smoke Tests كلها تمرّ. التفاصيل §④.

**خطوات النشر (مختصرة):**
1. Render → **New → Blueprint** → اختر المستودع (يقرأ `render.yaml`).
2. اضبط الأسرار (`sync:false`) — أهمّها `APP_KEY`, `APP_URL`, `INITIAL_ADMIN_EMAIL/PASSWORD`,
   أسرار `R2_*` و`R2_BACKUP_*`, و`VITE_API_URL` للواجهة. الجدول الكامل §③.
3. الإقلاع يشغّل `start.sh`: هجرات + بذر أساسي (أدوار + هيكل تنظيمي + **أوّل مدير تلقائيّاً**).
4. أعِد بناء `law-web` بعد ضبط `VITE_API_URL` (يُحقن وقت البناء).

**التحقّق (Smoke Tests):** `/up` = 200 → دخول المدير → إنشاء قضية → رفع/تنزيل مستند → نسخة
احتياطية يدويّة → تشغيل المُجدوِل. القائمة القابلة للتأشير §⑤.

**قرار Go/No-Go:** لا تُطلِق ما لم تمرّ **كل** بنود §④ و§⑤. عند الفشل: §⑥ (Rollback).

**ماذا يُسلَّم للعميل:** روابط الخدمات · حساب المدير الأوّل (تُدوَّر كلمته بعد أوّل دخول) ·
هذه الحزمة + الأدلّة المرتبطة · ملكيّة حساب Render وR2 والقاعدة والأسرار. التفاصيل §⑦.

**ما يتبقّى بعد B4:** 🟡 B5 (مراجعة أمنية نهائية) · 🟡 B6 (UAT بالأدوار الحقيقية).

**روابط:** [تفاصيل النشر](DEPLOY-RENDER.md) · [النسخ والاستعادة](BACKUP-RUNBOOK.md) ·
[حالة الإصدار](RELEASE-STATUS.md) · [دليل العرض](DEMO.md).

## ② المتطلّبات قبل النشر

- حساب **Render** (خطة مدفوعة `starter`+ للقاعدة والـ cron — الخطة المجانية تنام وتفقد بيانات
  القاعدة بعد 90 يوماً، ولا تدعم cron).
- دلوان في **Cloudflare R2** ومفاتيحهما: دلو للوثائق، و**دلو منفصل للنسخ الاحتياطي** (عزل أمني).
- **مزوّد SMTP** (اختياري لكن موصى به) لاستعادة كلمة المرور وبريد الإشعارات — أي خادم SMTP يعمل.
- `APP_KEY` مُولّد محليّاً: `cd backend && php artisan key:generate --show`.
- CI أخضر على `main` (Backend + Secret Scanning).

## ③ متغيّرات البيئة (جدول موحّد)

القيم `sync:false` أسرار تُضبط يدويّاً في لوحة Render بعد إنشاء الخدمات. الباقي مضبوط في
`render.yaml`. للتفاصيل والشروح: [DEPLOY-RENDER §قائمة المتغيّرات](DEPLOY-RENDER.md).

### `law-api` (الخلفية)

| المتغيّر | مطلوب؟ | المصدر/القيمة |
|---|---|---|
| `APP_KEY` | **مطلوب** (سرّ) | `php artisan key:generate --show` |
| `APP_URL` | **مطلوب** (سرّ) | عنوان `law-api` بعد الإنشاء |
| `INITIAL_ADMIN_EMAIL` | **مطلوب** (سرّ) | بريد أوّل مدير — يُنشأ تلقائيّاً عند الإقلاع |
| `INITIAL_ADMIN_PASSWORD` | **مطلوب** (سرّ) | كلمة قويّة — **تُدوَّر بعد أوّل دخول** |
| `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` · `R2_BUCKET` · `R2_ENDPOINT` | **مطلوب** (أسرار) | دلو الوثائق في R2 |
| `FRONTEND_URL` | موصى (سرّ) | عنوان `law-web` — يحصر CORS |
| `MAIL_MAILER` … `MAIL_FROM_NAME` (8) | لتفعيل البريد (أسرار) | بيانات SMTP — فارغ ⇒ `log` (لا إرسال، آمن) |
| `APP_ENV=production` · `APP_DEBUG=false` · `DB_*` · `CACHE_STORE` · `QUEUE_CONNECTION` · `LEGAL_DOCUMENTS_DISK=r2` · `R2_DEFAULT_REGION=auto` | مضبوطة | في `render.yaml` (DB مربوطة تلقائيّاً) |

### `law-scheduler` (المهام المجدولة — B3)

| المتغيّر | مطلوب؟ | المصدر |
|---|---|---|
| `APP_KEY` | **مطلوب** (سرّ) | **نفس** قيمة `law-api` |
| `MAIL_*` (8) | لبريد التذكيرات (أسرار) | نفس بيانات SMTP |
| `R2_BACKUP_ACCESS_KEY_ID` · `R2_BACKUP_SECRET_ACCESS_KEY` · `R2_BACKUP_BUCKET` · `R2_BACKUP_ENDPOINT` | **مطلوب للنسخ** (أسرار) | دلو النسخ **المنفصل** |
| الباقي (DB، CACHE، QUEUE، `R2_BACKUP_DEFAULT_REGION=auto`) | مضبوط | في `render.yaml` |

### `law-web` (الواجهة)

| المتغيّر | مطلوب؟ | المصدر |
|---|---|---|
| `VITE_API_URL` | **مطلوب** (سرّ) | `https://<law-api>/api` — **وقت البناء**، أعِد البناء بعد ضبطه |

## ④ قائمة Go / No-Go (قبل الإطلاق)

كلها يجب أن تكون ✅ قبل الإطلاق:

- [ ] CI أخضر على `main` (Backend + Secret Scanning).
- [ ] `APP_ENV=production` · `APP_DEBUG=false` (مضبوطة في `render.yaml` — تأكّد).
- [ ] `APP_KEY` مضبوط (نفس القيمة في `law-api` و`law-scheduler`).
- [ ] `INITIAL_ADMIN_EMAIL/PASSWORD` مضبوطان (المسار الرسمي لأوّل مدير).
- [ ] أسرار `R2_*` (وثائق) و`R2_BACKUP_*` (نسخ — **دلو منفصل**) مضبوطة.
- [ ] `VITE_API_URL` مضبوط و`law-web` أُعيد بناؤه بعده.
- [ ] الخطة مدفوعة (`starter`+) للقاعدة و`law-scheduler`.
- [ ] (إن فُعّل البريد) أسرار `MAIL_*` مضبوطة واختُبرت باستعادة كلمة مرور.
- [ ] كل Smoke Tests (§⑤) تمرّ.
- [ ] نسخة احتياطية أولى ناجحة موجودة (شبكة أمان قبل الإطلاق).

**أي بند ✗ = No-Go.**

## ⑤ Smoke Tests (بعد النشر — بالترتيب)

| # | الاختبار | معيار النجاح |
|---|---|---|
| 1 | `GET https://<law-api>/up` | `200` |
| 2 | فتح `law-web` في المتصفّح | الصفحة تُحمَّل بلا خطأ |
| 3 | دخول بحساب `INITIAL_ADMIN` | نجاح + ظهور وحدة تحكّم Super Admin |
| 4 | تصفّح المستخدمين/الأدوار/سجلّ التدقيق | تظهر بلا 403 |
| 5 | إنشاء قضية جديدة | تُنشأ وتظهر في القائمة |
| 6 | رفع مستند للقضية ثم تنزيله | يُرفع، يُنزَّل، ويطابق الأصل (جولة R2 فعليّة) |
| 7 | نسخة احتياطية يدويّة (`backup:run` من Shell أو **Trigger Run** على `law-scheduler`) | صفّ نسخة جديد + كائن في دلو R2 |
| 8 | **Trigger Run** على `law-scheduler` | السجلّ يظهر تشغيل المُجدوِل بلا خطأ |
| 9 | (إن فُعّل البريد) «نسيت كلمة المرور؟» | يصل رابط الاستعادة إلى البريد |

> رفع مستند (6) يثبت اتصال R2 الحيّ وصلاحيات المفاتيح؛ وقد تحقّق آليّاً أيضاً عبر سير عمل
> `R2 Integration` (راجع [RELEASE-STATUS](RELEASE-STATUS.md)).

## ⑥ خطة Rollback (عند فشل النشر)

**تراجع التطبيق (كود/إعداد):**
- من لوحة Render: **Deploys → Rollback** لخدمة `law-api`/`law-web` إلى آخر إصدار سليم.
- تغييرات الـ Blueprint تُعاد عبر Git (ارجع للـ commit السابق وادفع؛ Render يعيد المزامنة).

**تراجع قاعدة البيانات (عند تلف بيانات/هجرة):**
- الهجرات **أماميّة فقط** (لا `migrate:rollback` في الإنتاج). للتراجع عن حالة بيانات: **استعادة
  أحدث نسخة** عبر `php artisan backup:restore <id> --force` — عمليّة مدمِّرة مُحصَّنة. الخطوات
  الكاملة في [BACKUP-RUNBOOK](BACKUP-RUNBOOK.md).
- الوثائق على R2 لا تتأثّر بالاستعادة (تبقى كما هي).

**قاعدة:** خذ نسخة احتياطية **قبل** أي نشر يحمل هجرات جديدة (بند Go/No-Go §④).

## ملاحظة: أوّل مدير — المسار الرسمي

يُنشأ أوّل مدير **تلقائيّاً** عند الإقلاع من `INITIAL_ADMIN_EMAIL`/`INITIAL_ADMIN_PASSWORD`
(في `DatabaseSeeder`، idempotent — يُنشأ مرّة، ويُسنَد له دور `admin`). هذا **المسار الرسمي**:
مؤتمت، قابل للتكرار بأمان، ويقلّل الخطأ البشري عند التسليم. **لا حاجة لـ `tinker`.** بعد أوّل
دخول، دوِّر كلمة المرور من داخل النظام وأزل السرّ من لوحة Render إن رغبت.
