# ADR-002: اعتماد PostgreSQL بدل MySQL

- **Status:** معتمَد
- **التاريخ:** 2026-07-28

## Context (السياق)
النظام مالي/قانوني يتطلب **دقة نقدية مطلقة**، معاملات قوية، حقولاً مرنة (حمولات البصمة الخام، تفاصيل بنود الرواتب)، وبحثاً نصياً عربياً في القضايا والمستندات، مع نمو متوقع في جداول السجلات (بصمة، تدقيق، إشعارات).

## Decision (القرار)
نعتمد **PostgreSQL 16** كقاعدة بيانات علائقية أساسية.

## Alternatives Considered (البدائل)
| البديل | التقييم |
|--------|---------|
| **MySQL 8** | خيار صالح وناضج، لكن دعمه لـ `NUMERIC` الدقيق و`JSONB` والفهرسة المتقدمة (GIN/GiST) وصلاحيات الصفوف (RLS) أضعف مما نحتاج |
| **SQL Server** | ممتاز لكنه يرفع تكلفة الترخيص ويربطنا ببيئة محددة |
| **MongoDB (NoSQL)** | غير ملائم؛ النظام مترابط بعلاقات ومعاملات مالية تتطلب ACID |

## أسباب الاختيار (لماذا PostgreSQL)
- **`NUMERIC(15,2)`** دقيق للمبالغ (لا أخطاء تقريب عائمة) — حرج للمالية والرواتب.
- **`JSONB`** لحقول مرنة (raw_payload للبصمة، details لبنود الرواتب، settings) مع فهرستها.
- **Full-Text Search** ودعم أفضل للعربية، وتكامل مع Meilisearch للبحث المتقدم.
- **Partitioning** أصلي لجداول السجلات الكبيرة (attendance_logs, audit_logs, notifications).
- **RLS (Row-Level Security)** خيار احتياطي لتعزيز العزل عند الحاجة.
- **معاملات وقيود سلامة** قوية (CHECK, Deferrable Constraints).

## Consequences (النتائج)
**إيجابيات:** دقة مالية، مرونة، أداء تحليلي أفضل للتقارير، مسار SaaS أنظف (RLS).
**سلبيات/مقايضات:** خبرة الفريق بـ MySQL قد تكون أوسع محلياً (يُعالَج بالتدريب)؛ بعض أدوات الاستضافة المشتركة الرخيصة تفضّل MySQL (غير ذي صلة لأننا ننشر على خادم مُدار بـ Docker).

## When to Revisit (متى يُعاد النظر)
إذا فرض قيد استضافة/تشغيل خارجي MySQL حصراً، أو ظهرت خبرة تشغيلية حاسمة تميل للبديل. التصميم يبقى محايداً عبر ORM (Eloquent) بحيث يظل الانتقال ممكناً بكلفة محدودة.
