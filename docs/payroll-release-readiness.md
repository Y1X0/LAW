# Payroll Module — Release Readiness Review (Phase 2)

مراجعة جاهزية إصدار لطبقة واجهة وحدة الرواتب، بعد PR-1..PR-7. **لا تغيير على محرّك
الرواتب الخلفي في كامل Phase 2** — الواجهة فوق العقود الموجودة فقط. هذه المراجعة حكمٌ
مبنيّ على فحص شامل، لا على نجاح CI وحده.

## 1) رحلة المستخدم الكاملة (من المتصفّح)
| الخطوة | الشاشة | نقاط النهاية |
|---|---|---|
| إنشاء فترة | `/payroll/periods` | `GET/POST payroll-periods` |
| إعداد مكوّنات الراتب | `/payroll/components` | `GET/POST/PUT salary-components` |
| إعداد راتب الموظف | `/payroll/salary` | `salary-profiles` · `employees/{id}/salary-components` (+DELETE) |
| تشغيل المسير | `/payroll/runs` | لقطة حضور/إجازات → احتساب → اعتماد → قفل |
| عرض الكشف | `/payroll/runs/:id/payslips` | `payslips` · `payslip` · `payslip/html` |
| مراجعة التقارير | `/payroll/reports` | `payroll-reports/cost` · `.../employees/{id}` |

الرحلة كاملة قابلة للتنفيذ من المتصفّح دون لمس الخلفية. ✅

## 2) الصلاحيات
- **الواجهة:** كل مسارات `/payroll/*` (7) محمية بـ`RequirePayroll` (قدرة `payroll.view`) داخل `PayrollLayout`. من لا يملكها يُعاد لبوابته. روابط التنقّل تظهر فقط في بوابتَي HR/المالك (كلاهما يملك `payroll.view`).
- **الخادم (الحكم النهائي):** كل نقطة نهاية مقسّمة — قراءة `payroll.view` · كتابة `payroll.create` · اعتماد `payroll.approve` · قفل `payroll.pay`. لا نقطة نهاية غير محروسة.
- حماية مزدوجة (واجهة + خادم)؛ لا مسار يمكن الوصول إليه دون تصريح. ✅

## 3) واجهات المستخدم
- **الموبايل:** صفر جداول عريضة في الوحدة — كل القوائم بطاقات متجاوبة؛ شريط التنقّل الفرعي قابل للسحب أفقياً. ✅
- **سطح المكتب + التنقّل:** تنقّل فرعي موحّد فوق كل الشاشات (وحدة متماسكة لا شاشات متفرّقة). ✅
- **الحالات:** Loading (skeleton) · Empty (برسائل + CTA حيث يلزم) · Error (بإعادة محاولة) على كل شاشة. ✅
- **التأكيد قبل الحساس:** حوارات تأكيد قبل الاحتساب/الاعتماد/القفل (القفل: تنبيه لا رجعة)؛ تحذير عند الاحتساب دون لقطات (يعكس سماح الخادم، لا يخالفه). ✅
