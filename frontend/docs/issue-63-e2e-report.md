## 1) المسار السعيد الكامل (`e2e/happy-path.spec.ts`)

سيناريو واحد متّصل يغطّي رحلة الموظف من البداية للنهاية:

1. **تسجيل الدخول** — إدخال البريد/كلمة المرور، الضغط على «دخول».
2. **اللوحة** — التحقّق من التوجيه إلى `/dashboard`، ظهور الاسم والرقم الوظيفي وترحيب الشريط العلوي.
3. **كشوف الراتب** — التنقّل، ظهور الفترة والصافي المنسّق (`14,250.50 SAR`).
4. **تفاصيل الكشف** — فتح الكشف، ظهور المستحقات والخصومات.
5. **الطباعة** — الضغط على «طباعة» يجلب مستند HTML من الباك-إند (بترويسة `Authorization: Bearer`) ويفتح نافذة طباعة مكتوبة بالمحتوى الصحيح.
6. **الحضور** — عرض جدول السجلّات (قراءة فقط)، بما فيها حالة «متأخّر».
7. **الإجازات** — عرض الرصيد، ثم **تقديم طلب** بنجاح مع رسالة تأكيد.
8. **الملف** — عرض البيانات الوظيفية (للعرض فقط) وتعديل حقل «الهاتف» وحفظه بنجاح.
9. **تسجيل الخروج** — العودة إلى `/login`.

سيناريو ثانٍ يؤكّد أن **تعديل الملف يرسل الحقول المسموحة فقط** (`phone, address, photo_path, emergency_contact_name, emergency_contact_phone`) ولا يرسل أي حقل مالي/تنظيمي (`basic_salary, department, job_title, employee_id`).

## 2) حالات الفشل والحواف (`e2e/failure-cases.spec.ts`)

| # | الحالة | السلوك المتوقّع (وقد تحقّق) |
| --- | --- | --- |
| 1 | دخول خاطئ (401) | رسالة خطأ واضحة، البقاء في `/login`، **لا توكن مُخزَّن** |
| 2 | انتهاء الجلسة + فشل التجديد (401→refresh 401) | مسح التوكن وإعادة التوجيه إلى `/login` |
| 3 | تجديد التوكن الناجح بعد 401 | إكمال النداء بشفافية، حفظ التوكن الجديد، ظهور اللوحة |
| 4 | حساب غير مرتبط بموظف (403 `NO_LINKED_EMPLOYEE`) | رسالة «حسابك غير مرتبط بسجلّ موظف. تواصل مع الموارد البشرية.» |
| 5 | خطأ خادم (500) | حالة خطأ عامة بالرسالة العائدة |
| 6 | قوائم فارغة (كشوف/حضور) | رسائل الحالة الفارغة الصحيحة |
| 7 | أخطاء تحقّق (422) عند تقديم إجازة | ظهور الخطأ بجانب الحقل المعني |
| 8 | حماية المسارات دون جلسة | زيارة `/profile` و`/payslips` تُعيد إلى `/login` |

## الخلل المكتشف والمُصلَح 🐞

**الوصف:** دالّة الطباعة `printPayslip` كانت تفتح النافذة عبر
`window.open('', '_blank', 'noopener,noreferrer')`. تمرير `noopener` في وسم الميزات
يجعل المتصفّح يُرجع `null` دائماً، فتتوقّف الدالّة عند `if (!win) return` دون كتابة
المستند — أي **الطباعة لا تعمل فعلياً** (تُفتح صفحة فارغة).

**سبب عدم اكتشافه سابقاً:** اختبار الوحدة كان يُبدّل (mock) الدالّة `window.open`
لتُرجع كائناً وهمياً بغضّ النظر عن الوسائط، فلم يُلتقط سلوك `null` الحقيقي. E2E على
متصفّح حقيقي التقطه.

**الإصلاح (frontend، ضمن نطاق #63):** إزالة `noopener,noreferrer` — النافذة فارغة
ونفس-الأصل ونكتب فيها مستند الباك-إند بأنفسنا، لذا نحتاج مرجع `opener`. لا تغيير في
الـ API ولا في الباك-إند.

```diff
- const win = window.open('', '_blank', 'noopener,noreferrer')
+ const win = window.open('', '_blank')
```

بعد الإصلاح: اختبار E2E للطباعة يمرّ ويؤكّد كتابة المحتوى في النافذة الجديدة.

متصفّح Chromium، تشغيل `npm run test:e2e` (يبني وينشر preview تلقائياً)، ورفع تقرير
Playwright كأثر (artifact).
